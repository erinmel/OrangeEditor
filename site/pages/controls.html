Layout and theme

Controls take an egui::Ui and use your current panel style or the OrangeEditor tokens installed on its context. Keep values in application state. Call UiTokens::for_surface(ui, Surface::Card) when supplying a token set to card controls.

Call this once when you create your egui context to install OrangeEditor’s desktop style, including its text and spacing defaults.

orange_ui_controls::apply_desktop_style(ctx);

Start with the gallery to explore variations and states:

cargo run --locked -p orange-ui-controls --example gallery

Sliders and dials

Choose a continuous slider for a range, a logarithmic slider for positive values spanning several orders of magnitude, and a stepped slider when only discrete values are legal. A knob offers the same editable range in a narrow card. The return value is an egui::Response with changed().

Store level as an f32 in your app state, initialized to 55.0. Pass the same mutable reference to both controls each frame.

orange_ui_controls::continuous_slider(ui, Surface::Card, level, 0.0..=100.0);
orange_ui_controls::knob(ui, Surface::Card, level, 0.0..=100.0, None, &[]);

Buttons and choices

Use a button for a command, a switch for a persistent Boolean, and a segmented control for a small set of mutually exclusive options. Match on the selected value, keeping the display label independent of its stored representation.

let tokens = UiTokens::for_surface(ui, Surface::Card);
let caption = ui.label("Sample mode");
pill_segmented(ui, tokens, &caption, mode, &[(0, "Off"), (1, "Peak"), (2, "RMS")]);

Here mode is a mutable reference to application state. Segmented control API · Switch API

Selecting Peak stores 1 in mode. The live demo uses the same segmented control for Light and Dark.

Text and files

Use a text field for inline labels or values and a text area for multiline input. The password field lets the user reveal the value through an explicit action. Keep persisted credentials in the host’s credential store. A path picker exposes a browse action. Enable the optional native-dialogs feature for the desktop picker or supply the selected path from your application.

Give the field a stable ID and pass your mutable String as graph_name. The hint appears when the field is empty. Typing updates the string in your app state.

let id = ui.make_persistent_id("graph-name");
orange_ui_controls::text_field(ui, Surface::Card, id, graph_name, "Graph name");

Menus and dialogs

Use the shared menu and menu row controls for actions grouped under a command. Use a modal when the user needs to confirm or cancel before continuing. Keep the underlying operation and any file chooser in your application.

Show the modal while your app is waiting for a decision. Apply the rename only when the user clicks Rename, and clear the modal’s open state when they dismiss it.

let result = orange_ui_controls::modal(ui.ctx(), egui::Id::new("rename-graph"))
    .show(ui.ctx(), |ui| {
        ui.label("Apply the new graph name?");
        let rename = ui.button("Rename").clicked();
        if ui.button("Cancel").clicked() {
            ui.close();
        }
        rename
    });
if result.inner {
    apply_rename();
}
if result.inner || result.should_close() {
    *rename_open = false;
}

Meters and charts

A meter visualizes a measurement supplied by your application. Show level and peak independently. Frequency charts visualize caller-supplied bands or samples. Keep device routing and audio processing outside these widgets.

Supply normalized values between 0.0 and 1.0. This meter fills 40% of its height and draws a separate peak marker at 70%.

use orange_ui_controls::visualizations::{LevelMeter, MeterColors};

let bounds = egui::Rect::from_min_size(ui.next_widget_position(), egui::vec2(14.0, 72.0));
LevelMeter::vertical(0.4, 0.7).paint(ui, Surface::Card, bounds, MeterColors::standard());
