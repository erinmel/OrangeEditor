- **Supply chain:** weekly Cargo and GitHub Actions Dependabot update proposals, limited open PRs. Read-only token, no secrets, no `pull_request_target`, full SHA action pins, no persisted checkout credentials and explicit job timeouts. - **Core architecture:** a small Cargo metadata policy check rejects a direct or transitive Bevy dependency beneath `orange-model` (and known graph/compiler/runtime/contracts core members as they appear). Do not ban Bevy from the whole workspace: later host adapters may depend on it. When a package named `bevy` is present, enforce exactly `0.20.0` and exact `=0.20.0` workspace-member requirements, without incorrectly assuming every independently versioned `bevy_*` utility shares the engine version. Invalid/missing metadata fails closed. Absence of Bevy means its feasibility checks are inapplicable, not passed.

## Scoped implementation, SOLID / DRY / KISS

Use a single understandable workflow with stable `docs`, `policy`, `rust` status names. The `rust` aggregate runs after all required quality/platform/MSRV/security/policy jobs and fails for failure, cancellation or unexpected skip. Avoid nested security aggregate jobs, duplicate scanners, generic plugin abstractions, a custom CI framework and unrelated product changes. Keep checks as small independent jobs/modules and reuse the metadata logic for MSRV and dependency ownership where sensible.

Implement only the steps justified above. No Bevy dependency, harness, desktop application, release/deploy/signing job, binary artifact, project license selection, credentials, secret-bearing log, nightly/fuzz/Miri/coverage or performance gate. These are later work, not fake passing placeholders. Keep current dependency features/Cargo.lock/toolchain pin unchanged unless a concrete test failure requires a separately explained fix; report that to the parent first.

Potential owned files for the implementation agent: `.github/workflows/checks.yml`, `.github/dependabot.yml`, `deny.toml`, small focused scripts/tests under `tools/`, `tools/README.md`, and affected sections in `docs/06-quality-and-validation.md`, `docs/09-bevy-0.20.md`, `docs/10-tooling-and-sources.md`, `docs/14-git-workflow.md`. Do not edit application Rust code, research reports, this task, AGENTS.md, Cargo manifests/lockfile or user Git configuration. Ignore `.artifacts/local` in documentation traversal if the implementation worktree would otherwise cause scratch content to be audited; explain this narrow tooling correction.
