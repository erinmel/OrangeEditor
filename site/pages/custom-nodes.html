Make a node from a graph function

Use Make function when the logic can be expressed with nodes you already have. The editor extracts a graph-local function and replaces the selection with a call. Incoming and outgoing wires define the boundary ports. Multiple calls can reuse the same declaration with different arguments.

  1. Open power-with-count.json. Shift-click the cards that compute the result, leaving Calculate power, Base, Exponent, and Save result outside the selection.
  2. Choose Make function and inspect the boundary preview. The data inputs are a and count and the data output is value. Confirm as Compute power.
  3. Press Run and fire Calculate power. Confirm the default result is 81. Duplicate the call to use the same function elsewhere.

Write a Wasm component node

Start with the Rust guest example, the WIT world, and the expansion contract. Use an owned identifier such as org.example.text/normalize and give it versioned, concrete inputs and outputs. A small first node can take core/string@1 and return a normalized string.

  1. Declare the node under nodes/ and list its definition and provider slot in manifest.json. Add Fluent names under your package namespace. Ship English and Spanish text.
  2. Implement the generated guest export for your node. Match its inputs in declared order and return typed outputs in declared order. Select Pure for deterministic computations, Action for an execution step, or Async for work that needs supported host I/O. Keep granted I/O out of Pure evaluation.
  3. Build for wasm32-unknown-unknown with wit-bindgen, then wrap the module with orange-componentize. Set the manifest’s execution entry to the resulting component and request only the permissions used.
  4. Pack and install the package. Check a graph that uses the node and run it with normal input, invalid input, and any permission denied.

Build and test a component

The repository’s probe implements both nodes.evaluate and effects.execute. The host integration test puts the component into an archive, declares an Async node with an amount input and a result output, then verifies that the effect returns to its flow. Run the same test against a freshly built component:

rustup target add wasm32-unknown-unknown
node tools/build-guest-fixtures.mjs --out probe.wasm
ORANGE_GUEST_PROBE="$PWD/probe.wasm" cargo test -p orange-host --locked --test host an_installed_package_node_runs_on_a_worker_and_returns_to_its_flow -- --exact

In PowerShell, set $env:ORANGE_GUEST_PROBE = (Resolve-Path probe.wasm).Path before running the Cargo test. For a simpler archive without Wasm, use the Remember fixture.

Add trusted Rust services

For an application-owned Rust integration, use ServicePackage and ServiceNode from orange-sdk and register the package with Host::with_services. Implement ServiceSource for an owned trigger source or ConnectionAdapter for a connection kind. See the SDK reference and the Shout example for a definition paired with a Rust implementation.
