Add the headless host

Use orange-host as the Rust boundary for graph authoring and execution. The project’s crates are currently workspace packages. Pin the same repository revision for each OrangeEditor dependency. Replace the example revision as a set when upgrading.

[dependencies]
orange-host = { git = "https://github.com/erinmel/OrangeEditor.git", rev = "@revision@" }

For a local checkout, point a path dependency at app/crates/platform/orange-host. Add application services with Host::with_services when your graphs need nodes or connection adapters beyond what Host::new provides.

Attach a front end

  1. Create one Host and keep the Events receiver. Query host.nodes() and host.packages() for your library and package list.
  2. Use Host::check to validate saved JSON. Use Draft and the host’s authoring methods for editable graphs and GraphView for presentation.
  3. Call host.open and keep the FlowId. Call host.observe when displaying live values and host.trigger to fire a manual entry.
  4. Consume FlowEvent updates by flow ID. Stop the flow with StopMode::Graceful when appropriate and close it when finished.
cargo run -p orange-host --example attach --locked

The complete attach example checks a graph, fires a manual entry, waits for its variable update, and closes the flow. In a GUI, drain events without blocking the UI thread.

Decide what the application owns

The host manages drafts, validation, executing flows, and package bindings. Your application owns the file picker, persistence locations, OS credentials and authorization policy, services you expose, and application commands. Use the egui integration for the supplied editor or draw a front end using the same host.

See the embedding contract and orange-host Rustdoc.
