# Product requirements

## Perspective and success

OrangeEditor is a **usable node editor foundation** (ADR-21/22): an embeddable Rust graph core, a separate reusable and extensible egui editor UI, and a basic application. People can use the application directly or build specialized products on its libraries. The foundation owns a strong node language and general capabilities; downstream products and installed plugins supply specialized workflows. Desktop and headless execution consume the same graph and package locks. The editor is a client of the runtime, not its clock.

Success means a user can configure a trigger on its node, declare/Get/Set typed variables, branch/loop over calculations, save selected logic as a callable specialized node, export/import it with dependencies, and inspect execution and failures. A third party can install a synthetic expansion while the app stays open, contribute a node, event source and editor configuration, run it, and remove it without losing the document. Downstream products use public Rust interfaces without forking the core. Speed and usability require measured evidence.

Priority: **M** required for the foundation 1.0; **S** optional/deferred, not a 1.0 gate. Phase: **P1** feasibility, **P2** language/runtime/expansion, **P3** editor and reusable graphs, **P4** triggers/files/connections, **P5** audio and qualification, **P6** optional extensions. FR IDs are stable: retired requirements retain their IDs. ADR-22 supersedes older integration and protocol release scope.

| Area | Foundation commitment |
|---|---|
| Language | Typed logic/math, strings/collections, variables declared/read/written through nodes, enum construction/matching, structured loops, branching, time, errors and cancellation |
| Authoring | Usable extensible UI, save/load/recovery, import/export, groups, typed callable reusable graphs and reusable graph templates |
| Triggers | On-node manual/test button and configurable key or combination; timers/custom events; one shared event-source contract for later plugin triggers |
| Automation | File editing/watch, HTTP/HTTPS requests and WebSocket sessions; MQTT is conditional on a bounded broker/lifecycle feasibility slice |
| Audio | Open/play/control files, select available output and input devices, basic mix/gain, RMS/peak levels and above/below-threshold events with optional hold duration |
| Conditional | MQTT, frequency-band/pitch analysis and webhook listener plugins require focused contracts/evidence before promotion; they do not block baseline |
| Specialized plugins | OBS, Twitch, website-specific APIs, TTS generation, browser-canvas/web-server integrations and scene systems are outside this delivery. Generic requests and playback of plugin-produced audio remain in scope |

**Core-first delivery sequence.** Finish validation and compilation, then deterministic headless execution for math/logic, seeded random, virtual time, loops, cancellation and resource ownership, with inert in-memory service adapters. Concrete services, package loading and UI remain later bounded slices; early evidence is collected when a public boundary needs it. This sequencing does not remove the foundation UI or services and passes no API/runtime gate by itself. [06](06-quality-and-validation.md) defines verification; the local plan orders delivery.

**Validation review corrections (2026-10-23).** FR-44/46 availability follows persisted Sequence order; FR-12/44 resource storage rules include nominal record fields and enum payloads, including recursive schemas; FR-44 config bounds preserve integer precision; and FR-44/46 exports stop at state outputs while computed cones retain activation checks. NFR-05/08/15 verification and remaining complexity limits are recorded in [10](10-tooling-and-sources.md#security-and-performance-verification-2026-10-23). These corrections add no runtime, compilation-readiness or performance gate claim.

## Glossary

| Term | Meaning |
|---|---|
| Definition | Versioned declarative node/type description; contains no executable code |
| Implementation/provider | Executable realization of a definition or replaceable service slot |
| Package / expansion plugin | Installable OrangeEditor artifact containing definitions, executable components, assets and dependencies |
| Bundled package | Shipped package using public contracts; native kernel exception is explicitly identified |
| Snapshot | Immutable registry and provider choices pinned by a compiled execution |
| Activation | One invocation started by an entry node or event, with frame-local values; contains one or more strands |
| Run | Owned execution lifetime, variables, subscriptions, cancellation and resources; executed by one logical actor |
| Strand / segment | One control token's path through an activation / one uninterrupted execution of a strand between suspension or yield points |
| Region | Exec nodes owned by one structured construct (entry, event, Sequence step, Fork branch, loop body, function) |
| Epoch | One pull evaluation of the data inputs at a consumption site; the unit of volatile snapshot and memoization |
| Node kind | `pure`, `volatile`, `action`, `async`, `entry`, `iterator`, control/zone intrinsic, function call ([11](11-graph-language.md)) |
| Data / exec / event port | Typed value dependency / ordered control continuation / output that starts a new activation per event |
| Resource handle | Opaque capability and lifetime reference; never a serialized pointer or engine entity ID |
| Connection profile / session | Persisted configuration with secret references / live authenticated transport |
| Override slot | Named, typed and documented replacement interface with visible provider selection |
| Get/read variable | One `volatile` operation, named Get; read in each consuming epoch's prologue, never a write |
| Internationalization (i18n) / localization (l10n) | Architecture making all product text translatable / translated and reviewed resources for a particular locale; Unicode input alone provides neither |

## Workflows and boundaries

Structured headless milestone (2026-10-24; FR-04/08/10/12/14/16/44-47, NFR-02/05/08/14): the executable control subset now includes Start/Stop, Branch, Sequence, Count/While, Break/Continue, Wait/Yield and local/run Get/Set. It uses checked plans, frozen provider snapshots, budgeted data/control safe points, virtual time and staged drain/cancel/dispose with bounded cleanup. Independent source/control properties and known answers qualify this subset; they do not complete every referenced FR or any general performance/platform gate. Timer entry events (FR-15), functions, other executable types/kernels, Update/shared state, notifications/Watch, general resources/services, checkpoint persistence, extension/API qualification and V12/NFR work remain open.

E3 control execution trace (2026-10-24; FR-04/08/12/14/16/44-47): checked Start/Stop/Branch plans and bounded data safe points now support headless local/run Get/Set execution for the admitted plan types, with initializer validation, consumption snapshots and original uninitialized-read fault identity. This supersedes older claims that all mutation execution is absent, only for these Get/Set operations. Update/shared state, full structured execution, events/resources and qualification remain separate slices. Exact evidence is recorded in 10 when the integrated PR candidate is qualified.

1. **Logic and reuse:** declare a typed variable → calculate/branch/loop → Get/Set → inspect → save selected logic as a callable node → export/import and obtain the same outputs with the same seed and locks.
2. **Trigger:** configure a key combination on its node, or press its test button → enqueue an activation → inspect the payload. Plugin events later use the same path; editing a binding never executes effects.
3. **Automation:** file watch or timer → bounded read → transform → HTTP request or WebSocket send → typed success/failure handling. MQTT is a conditional adapter, not an assumption that all IoT protocols ship.
4. **Audio:** select input → level remains above a threshold for a configured duration → trigger → play an opened audio file on a selected output/cable → adjust volume. A future TTS plugin supplies an audio asset or bounded PCM stream to the same playback service.
5. **Expansion and recovery:** install a synthetic plugin while open → grant authority → use its node/trigger/editor → update while a run stays pinned → remove without document loss. A failed save/install/migration recovers the last committed generation without replaying effects.

Foundation 1.0 excludes OBS/Twitch and other website-specific integrations, browser-canvas/web-server products, AMQP, GraphQL and gRPC packages, TTS generation, speech recognition, a DAW/DSP or scene editor, virtual-device/driver creation, arbitrary monkey-patching, hard real-time certification, distributed execution, collaboration and marketplace operation. Optional proposals retain their own evidence gates and do not count as foundation requirements. Generic HTTP and resource handles remain usable by later plugins.

Graph-language requirements FR-44–50 are specified normatively in [11](11-graph-language.md) and [12](12-graph-data-structures.md) and are delivered first by WU-00. FR-51 is specified in [13](13-internationalization.md), with message schemas before SDK freeze and UI qualification before authoring preview. Verification families are mapped in [06](06-quality-and-validation.md); local work-unit planning and its coverage matrix live in ignored `.artifacts/`. No M foundation requirement can be silently deferred to claim 1.0 complete; previews label their subset. FR-52–56 add authoring/service scope without changing the closed control language or passing implementation gates.

Validation evidence clarification (C4, 2026-10-23; FR-44–47): combined analysis reports the checks it actually ran and the required checks still missing. Compile readiness requires complete coverage, a pass-local valid report, and matching document-state and registry identities. Semantic coverage includes contextual contracts, regions, declaration types and state metadata. A fresh valid report can permit compiler lowering; compiler-owned constant evaluation remains missing, so no completed plan is compile-ready; see [12 §3.2](12-graph-data-structures.md).

Readiness fixes (2026-10-23; FR-44–47, NFR-05/08/15): declaration-wide type validation, linear dependency representation for wide computations, combined-analysis admission quotas/cancellation, and distinct semantic-lowering versus completed-plan readiness are implemented and verified in [10](10-tooling-and-sources.md#readiness-fixes-verification-2026-10-23). These controls preserve graph content and fail closed on rejected analysis. Constant evaluation, runtime execution, hard per-pass interruption and mixed-workload NFR qualification remain separate work.
Native scalar prerequisite (N1a, 2026-10-23; FR-10/44, NFR-05/14): orange-bundled implements six primitive numeric specializations of Add/Subtract/Multiply/Divide plus boolean Not, with explicit config, stable safe errors, exact provider resolution and pinned registry metadata. Product-definition graphs pass semantic validation; a known-answer binding returns 42. Overflow, zero division, IEEE/finite rules, mixed-type rejection and wider-integer property oracles are verified in [10](10-tooling-and-sources.md#bundled-scalar-kernels-verification-2026-10-23). This is partial FR-10 delivery; conversions, the compiler/reference evaluator, control execution and runtime/qualification gates remain open.
Core converter execution (N1b, 2026-10-23; FR-10/44/45, NFR-05/14): the four existing explicit core converters execute with checked range, fixed saved policies, exact Core selection and pinned metadata. Float widening retains NaN bits and narrowing returns the specified loss flag without raw-value exposure. Known-answer/property and saved-graph validation evidence is recorded in [10](10-tooling-and-sources.md#core-converter-execution-verification-2026-10-23). This remains a scalar subset: compiler/source-map/constant-error proof and graph reference evaluation are not implemented by these APIs.
Pure-export implementation trace (E1a, 2026-10-23; FR-07/08/10/14/44/45, ADR-01/15/16/20): orange-compiler now lowers fresh validated root pure eager scalar/JSON graphs to immutable typed slots, source maps, pinned executable bindings and folded exports. A shared producer folds once; fault propagation follows declared input order, retains its original producer and remains observable through exports, with W-CONST-ERROR. Missing backends, stale evidence, unsupported semantics and resource/cancellation failures publish no plan. This fulfills a bounded part of the compiler contract; full ExecutionPlan, general constant-evaluation coverage, independent interpreter equivalence, API release and NFR gates remain open. ValidationAnalysis still does not certify full compilation.

Import/export performance clarification (2026-10-23; FR-05/08, NFR-05/08): versioned JSON remains the saved editable graph contract; typed values/dense slots remain the in-memory execution representation. Removed a redundant full-document Serde flattening layer from JSON import while retaining header/version-first behavior, resource/duplicate checks, unknown-field order and canonical export bytes. One new envelope-order regression and the existing codec/round-trip properties pass. An isolated named-MessagePack comparison is descriptive evidence for retaining the current format, not a new binary importer or a completed startup/NFR gate. See 10 for measurements and scope.

Independent pure-oracle evidence (E2a, 2026-10-23; FR-08/10/14/44/45, ADR-20): a test-only graph demand evaluator now checks compiled integer/boolean export values and original fault producer/code, using independent widened arithmetic and traversal. Bounded generated DAGs and explicit known answers exercise sharing, edge/literal/default precedence, overflow policies, error order, export order and JSON round trips. No production mismatch was found in these cases; no production behavior/API/schema changes were needed. General reference/runtime execution and release/NFR gates remain open; see 06 and 10 for the exact scope and limitations.

Checked export-consumer trace (E2b; FR-04/08/14/44/45, 2026-10-23): PurePlan::evaluate now exposes ordered borrowed typed exports with source ports and original graph fault provenance, guarded by freshness, export-count limits and cooperative cancellation. Started views preserve pinned immutable results across later edits/registry updates; new starts reject stale inputs. Independent integer-DAG oracle comparisons now consume this public path. This completes a restricted pure result-access slice only; scheduling, activation/epoch state and full execution gates remain open.

Floating export evidence (E2c, 2026-10-24; FR-08/10/44/45): reference/public-result comparisons now include bounded f32/f64 graphs, all four Core numeric converters and both typed result/loss outputs, including original range-fault provenance. Three bounded graph/converter properties run 128 cases each, paired with named boundaries. No production discrepancy was found; no production correction, new format or execution-domain expansion was introduced. Shared floating primitives and unqualified general runtime/NFR gates remain explicit in 06/10.

Constant lazy-selection trace (E1/E2d, 2026-10-24; FR-08/10/14/44/45): core/select, core/and and core/or now fold only the chosen input cone in the supported pure scalar/JSON compiler. Executable resolution, literal materialization and folding skip unselected inputs; whole-graph semantic validation and conservative admission still inspect all relevant source metadata/potential cones.
